Share with leadership

  • Friday is now an agent platform: models use real tools — web search and page reading, code execution, the user's GitHub/Gmail/Drive/Calendar/Notion/Vercel/Railway/Supabase/Razorpay, and any MCP server.
  • Coding agent: Build Mode plans, edits, searches code, imports a GitHub repo and opens a pull request.
  • New for users: long-term memory, Deep Research reports, scheduled Automations with push, search across all chats, shareable chat links.
  • To go live: apply Supabase migrations 0001–0027, set production secrets, deploy, then check /api/health/ready.

4. How chat works (agent loop)

sequenceDiagram
  actor U as User
  participant FE as App
  participant API as Friday API
  participant DB as Supabase
  participant M as AI model
  participant T as Tools

  U->>FE: Message (+ files, Search / Deep Research)
  FE->>API: POST /api/chat/.../stream with JWT
  API->>API: Rate limit + token quota reservation
  API->>DB: Save message, load history + memory + project
  API->>API: Intent probes (search / build / image) in parallel
  alt Build request
    API->>API: Build Mode coding agent (see diagram 12)
  else Model supports tools
    loop up to 8 rounds (16 for Deep Research)
      API->>M: Stream turn with tool list
      M-->>API: Text and/or tool calls
      API->>T: Run tools in parallel (web, code, GitHub, Gmail, MCP...)
      T-->>API: Results (treated as untrusted data)
      API-->>FE: SSE text + step rows + citations
    end
  else No tool support
    API->>M: Plain streaming with failover + hedging
    M-->>API: Tokens
  end
  API->>DB: Save reply, steps, citations, token usage
  API-->>FE: done

    FE->>API: POST /login
    API->>DB: Check password
    API->>Mail: Send 6-digit OTP
    U->>FE: Enter OTP
    FE->>API: POST /verify-otp
    API-->>FE: Session JWT
  else Google
    U->>FE: Continue with Google
    FE->>API: GET /auth/google/start
    API->>G: OAuth consent
    G-->>API: Code
    API->>DB: Create or reuse user
    API-->>FE: Hash friday_session
    FE->>FE: Store JWT locally
  else Company SSO
    U->>FE: Continue with Company SSO
    FE->>SSO: SSO_ENTRY_URL
  end

11. Agent tool loop

flowchart TD
  In[User turn] --> Pre[History + memory + project + current date + tool guidance]
  Pre --> Pick{First candidate model supports tools?}
  Pick -->|No| Plain[Plain streaming with failover + hedging]
  Pick -->|Yes| Round[Stream a model turn with the toolset]
  Round --> Calls{Tool calls?}
  Calls -->|No| Done[Save reply, steps, citations, usage]
  Calls -->|Yes| Run[Run tools in parallel, 45s timeout each]
  Run --> Feed[Append results as untrusted tool messages]
  Feed --> Compact[Compact old results beyond 180k chars]
  Compact --> Last{Last round?}
  Last -->|No| Round
  Last -->|Yes| Force[tool_choice none: force final answer]
  Force --> Done
  Round -. model rejects tools before any output .-> Plain
  Plain --> Done

  subgraph Toolset
    W[web_search / fetch_url - SSRF guarded]
    X[run_code - E2B]
    Mem[remember / forget]
    Con[GitHub Google Notion Vercel Railway Supabase Razorpay]
    Mc[MCP server tools]
  end
  Run --- Toolset

13. Automations scheduler

flowchart LR
  User[User] --> Page[Automations page]
  Page --> Api["/api/automations"]
  Api --> T[(automations table)]
  subgraph Every API instance
    Tick[Scheduler tick every 60s] --> Due[Select due rows]
    Due --> Claim[Atomic lease UPDATE running_until]
  end
  T --> Due
  Claim -->|won the lease| Quota{Token quota OK?}
  Quota -->|No| Fail[Record error, reschedule]
  Quota -->|Yes| Chat[Normal chat pipeline with tools + memory]
  Chat --> Conv[(Automation's own chat thread)]
  Chat --> Push[Push notification]
  Chat --> Next[Compute next run in user time zone - DST safe]
  Next --> T
  Fail --> T
