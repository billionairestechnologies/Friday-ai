In one page

  • Friday is an agent platform. Models use real tools (web, code, documents, the user's connected apps, MCP servers), remember users, run scheduled automations, and Build Mode is a coding agent that opens GitHub pull requests.
  • One account, every surface. Web, Android, iOS and now Friday X, a terminal and editor coding agent (VS Code, JetBrains, Zed). One plan, one model list, one usage meter.
  • The backend decides. Plans, entitlements, models and limits are edited in the Team Console and reach every client at once, with no app update.
  • Usage is metered in credits (what a call really costs us), enforced per round, and shown to users only as percent and reset time.
  • Company back office: support, CRM, plans and offers, finance and profit controls, mail hosting, status page with incidents and crash reports.

8. How chat works (agent loop)

sequenceDiagram
  actor U as User
  participant FE as App
  participant API as Friday API
  participant DB as Supabase
  participant M as AI model
  participant T as Tools

  U->>FE: Message (+ files, Search / Deep Research)
  FE->>API: POST /api/chat/.../stream with JWT
  API->>API: Rate limit + token quota reservation
  API->>DB: Save message, load history + memory + project
  API->>API: Intent probes (search / build / image) in parallel
  alt Build request
    API->>API: Build Mode coding agent (see diagram 12)
  else Model supports tools
    loop up to 8 rounds (16 for Deep Research)
      API->>M: Stream turn with tool list
      M-->>API: Text and/or tool calls
      API->>T: Run tools in parallel (web, code, GitHub, Gmail, MCP...)
      T-->>API: Results (treated as untrusted data)
      API-->>FE: SSE text + step rows + citations
    end
  else No tool support
    API->>M: Plain streaming with failover + hedging
    M-->>API: Tokens
  end
  API->>DB: Save reply, steps, citations, token usage
  API-->>FE: done

9. Agent tool loop

flowchart TD
  In[User turn] --> Pre[History + memory + project + current date + tool guidance]
  Pre --> Pick{First candidate model supports tools?}
  Pick -->|No| Plain[Plain streaming with failover + hedging]
  Pick -->|Yes| Round[Stream a model turn with the toolset]
  Round --> Calls{Tool calls?}
  Calls -->|No| Done[Save reply, steps, citations, usage]
  Calls -->|Yes| Run[Run tools in parallel, 45s timeout each]
  Run --> Feed[Append results as untrusted tool messages]
  Feed --> Compact[Compact old results beyond 180k chars]
  Compact --> Last{Last round?}
  Last -->|No| Round
  Last -->|Yes| Force[tool_choice none: force final answer]
  Force --> Done
  Round -. model rejects tools before any output .-> Plain
  Plain --> Done

  subgraph Toolset
    W[web_search / fetch_url - SSRF guarded]
    X[run_code - E2B]
    Mem[remember / forget]
    Con[GitHub Google Notion Vercel Railway Supabase Razorpay]
    Mc[MCP server tools]
  end
  Run --- Toolset

20. FridayX sign-in (device code)

sequenceDiagram
  actor U as User
  participant C as friday (CLI or editor)
  participant API as Friday /api/x
  participant W as Web app /device
  participant DB as cli_device_codes + cli_tokens

  U->>C: friday login (or first run)
  C->>API: POST /oauth2/device/code
  API->>DB: Store hash(device_code) + user_code, 10 min
  API-->>C: user_code, verification_uri_complete
  C->>U: Opens browser, prints ABCD-EFGH
  U->>W: Sign in to Friday (if needed)
  W->>API: GET /auth/device/ABCD-EFGH
  API-->>W: Which client is asking
  U->>W: Check the code matches, Approve (or Deny)
  W->>API: POST /auth/device/approve
  API->>API: FridayX entitlement checked
  API->>DB: status = approved (compare-and-set)
  loop every 5 s
    C->>API: POST /oauth2/token (device_code)
    API-->>C: authorization_pending
  end
  C->>API: POST /oauth2/token
  API->>DB: Claim once, store hash(fxt_ token)
  API-->>C: access_token fxt_...
  C->>C: Save token, then every request carries it
  Note over U,DB: Settings, FridayX lists every signed-in device. Sign out revokes the token at once.
